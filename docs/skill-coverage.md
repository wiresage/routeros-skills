# Skill coverage

Generated by `python tools/skill_coverage.py --write`. Do not edit by hand: change a `SKILL.md`, `tools/scopes.json` or `tools/coverage_policy.json` and run the command again. CI fails when this file is stale.

Every page of the manual is in some skill's `references/` folder. An agent opens a reference only when the skill leads it there, so this page measures how much of each skill's references its `SKILL.md` **names**:

- A guide or help-only page is *named* when `SKILL.md` links its file or its folder.
- A CLI menu is *named* when `SKILL.md` writes the menu path (`/ip firewall filter` or `/ip/firewall/filter`) or links its file or folder. It is *named elsewhere* when only another skill's `SKILL.md` does.
- A page that is not named is still in `references/` and in the skill's `INDEX.md`, so an agent can find it by browsing. Nothing tells it to look. That is a gap in the routing, not in the documentation.
- Product manuals and regulatory texts are looked up with a script or the index and are not counted.
- The counts leave out what `tools/coverage_policy.json` excludes, with a reason.

## Improving a number

1. `python tools/skill_coverage.py --list <skill>` prints everything that skill does not name.
2. Teach it in `SKILL.md` (a recipe with the menu path, or a row in the routing table that links the file or its folder), or move the page to the skill that should own it in `tools/scopes.json`.
3. A page that should not be routed goes into `tools/coverage_policy.json` with a reason.
4. Run `python tools/skill_coverage.py --write` and commit the new report with the change.
